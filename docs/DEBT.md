# Known gaps

## Bugs

A review of the whole tree in October 2026 found these. Each gives a wrong result, corrupts state or reports a misleading error instead of stopping cleanly. None is fixed yet, and most have no fixture that would catch them.

### Lifter

- Legacy-encoded scalar SSE instructions clear the destination above their scalar. `Read` truncates a vector register to the operand size Zydis reports, which is 32 or 64 bits for the legacy `addss`, `sqrtsd`, `cmpss`, `cvtss2sd`, `cvtsi2sd` and the rest, so the merge base that `EmitFloatArithmetic` and `EmitFloatConversion` build is zero above the scalar: `addss xmm0, xmm1` leaves `xmm0` as `{sum, 0, 0, 0}`. The VEX forms, which the fixtures use, are right, and `VectorMove` already reads the whole register for `movss`.
- `lock` is honoured only on `add`, `sub`, `and`, `or`, `xor`, `inc`, `dec`, `xchg`, `xadd` and `cmpxchg`. Locked `bts`, `btr`, `btc`, `adc`, `sbb`, `neg` and `not` become a load and a separate store, so two threads can both take the same bit, and nothing reports it. Other prefixes and branch types are not checked in one place either: a 16-bit `push` or `pop` moves `rsp` by 8, the 14-byte `fnstenv` and `fldenv` format is read and written as 28 bytes, `rep movs` and `rep stos` ignore an address-size override and a segment override on the source, and a far `call`, `jmp` or `ret` is lifted as a near one (a far `ret` pops 8 bytes; a far call through memory fails module verification without an address).
- A conditional jump whose fall-through is another function's start does not tail-call it. Discovery makes the fall-through a leader without decoding it, the lifter closes the empty block with `unreachable`, and LLVM deletes the edge, so the path not taken runs the taken one. A call to a `setjmp`-family import whose return address is another start does the same. A straight-line fall-through is a tail call, as [the design](DESIGN.md#control-flow) says.
- Overlapping instructions get a wrong edge. When the lifter reaches a leader with its block still open it branches to the leader even if the previous instruction ends elsewhere, so in `je 0f; lock; 0: cmpxchg` the locked path runs the `cmpxchg` twice and reports a successful exchange as failed.
- `movs` and `stos` clear CF, ZF, SF, OF, PF and AF: `StringOp` reloads the cached registers as after a call, where the status flags are dead, but they are live across a string instruction. The runtime also moves each element with its own `memmove` or `memcpy` call, and under `--memory tso` neither is ordered.
- `div` and `idiv` never raise #DE. A zero divisor or a quotient that does not fit is an LLVM `udiv` or `sdiv` with undefined behaviour or a truncated result, where x86 delivers SIGFPE. Every 64-bit division also divides in 128 bits, which is a compiler-rt call on aarch64.
- Under `--memory tso` some guest loads of 64 bits or less are plain: the memory forms that `ReadRegisterOrMemory`, `HalfMove` and `insertps` load (`movlps`, `movhpd`, `movddup`, `cvtps2pd`, `cvtdq2pd`, `vcvtph2ps` and others), and every x87 memory operand, which [the x87 runtime](../runtime/src/X87.cpp) copies with `memcpy`.
- `xadd` with the same register as both operands leaves the old value instead of the sum, because the destination is written before the source.
- Legacy `cmpps`, `cmppd`, `cmpss` and `cmpsd` take the predicate from bits 3:0 of the immediate rather than 2:0, so immediates 8 to 15 select predicates only the VEX forms have.
- `vcvtps2ph` with an immediate rounding mode turns +0 into the smallest denormal when it rounds up and −0 when it rounds down, because `SingleToHalf` adds the implicit bit to a zero exponent, and it ignores DAZ, unlike the form that takes MXCSR's mode.
- Guest tail jumps are `tail` calls, which LLVM may ignore and does at `-O0`, and an indirect `jmp` through dispatch is not marked at all, so a long chain of guest tail jumps can exhaust the host stack. Caller and callee share a prototype, so `musttail` would be legal.

### x87

- `fscale` by +∞, or by 2^63 or more, scales down to zero: under SoftFloat's 8086-SSE specialisation `extF80_to_i64` returns `INT64_MIN` on positive overflow, and the clamp keeps it negative. The invalid cases 0 × 2^+∞ and ∞ × 2^−∞ do not raise IE.
- Unnormals, pseudo-NaNs and pseudo-infinities are computed with as SoftFloat normalises them, instead of raising IE and returning the indefinite; `fxam` already classifies them as unsupported.
- A `fist` that overflows its 16- or 32-bit destination leaves C1 set from the 64-bit conversion. `fxam` of an empty ST(0) reports C1 as 0 rather than the sign of the stale register.

### Discovery and images

- [Discovery](../lifter/src/Discovery.cpp) decides whether an address a RIP-relative `lea` takes is a function by how the next few instructions use it. That lets data through: a string or table in an executable segment whose address is passed to a call, stored or spilled is decoded as code, which stops the lift or adds bogus call targets. It also misses functions whose address is returned, passed to a tail call (`lea rsi, [rip+init]; jmp pthread_once`), copied to another register first or stored through a vector register, or whose `lea` is followed by NOP padding that names the register. A target inside a known function splits it, which can cut a guarded jump table off from its jump. Each new start costs another round of discovery over the whole image, and an error in a start found this way does not name the `lea`. Checking the target itself (that it lies between known functions and decodes cleanly to a terminator) would replace the use patterns.
- `TableBound` accepts a `cmp`/`ja` guard reached through its taken edge, where the index is above the bound; walks past calls that clobber a caller-saved index, which `ReachingDefinitions` does not; and takes `sub idx, K; ja` as a bound on the result, which wraps. Each gives a table that is marked guarded but too short, whose missing cases stop in `ps5lift_dispatch`. A guarded table whose entries run past readable data is also cut short there without an error.
- The linear sweep keeps only data references outside executable segments, so a reference into a table that shares a segment with code does not end the table before it.
- Every export in an executable segment is a start, whatever its symbol type, so exported data there is decoded as code.
- `CalledImport` recognises a PLT stub only when its first instruction is the `jmp`, so a call to `setjmp` through an IBT stub (`endbr64; bnd jmp`) gets no resume point; the fixtures build with `-fcf-protection=none`. Its stub probe decodes outside `DecodeReached`, so an undecodable call target fails without naming the call.
- [GuestImage](../lifter/src/GuestImage.cpp) binds an unresolved weak undefined symbol to a synthetic import instead of 0, binds an `STT_GNU_IFUNC` definition to its resolver, adds the load bias to `SHN_ABS` symbols, and treats `R_X86_64_64` against symbol 0 as an import with an empty name. It skips a relocation table whose size tag is missing, takes a missing `DT_INIT_ARRAYSZ` as no initializers and `DT_SYMENT` as 24 without checking, and ignores `DT_RELR`, so a module linked with `-z pack-relative-relocs` gets none of its relative relocations. Its filter for the CIE personality also drops LSDA landing pads outside their FDE, which then are not resume points.

### Runtime

- A fiber resumed on another thread keeps running on the first thread's `Ps5LiftState`: [GuestCpu](../runtime/src/GuestCpu.cpp) restores its registers into the current thread's state, but each lifted and bridge frame on the fiber's stack holds the state it was entered with.
- [`Callback`](../runtime/include/ps5lift/Bridge.hpp) makes a thunk of any non-zero value, so `signal(sig, SIG_IGN)` installs a handler that dispatches to address 1. A guest function pointer inside a record, such as `sigaction`'s handler, reaches native code as a raw guest address, which native code then calls as host code.
- [`cpuid`](../runtime/src/Cpuid.cpp) reports CX16, SSE4.2, RDRAND, RDSEED, RDPID, RDTSCP, LAHF/SAHF, PREFETCHW and `xgetbv` with ECX=1, none of which the lifter lifts (and `xgetbv` with ECX=1 stops), so code that picks a path by `cpuid` takes one that stops at run time where its fallback would run.
- Guest stacks are a fixed 8 MiB with no guard page, whatever size the guest asks for, so an overflow writes into the mapping below.
- `Ps5LiftState::Rip` is never written, so a `sceKernelRaiseException` handler sees `rip` as 0. The handler runs 64 KiB below the stack pointer of the target thread's last call, which overwrites a frame that has grown past that since.
- `~ForeignThread` leaves `CurrentState` pointing at the state it frees, so a callback later in the thread's teardown runs on unmapped memory. A native thread that calls a guest callback, or only queries the guest state, keeps the guest's FPCR (DAZ, FTZ, AH and the rounding mode) for its own code afterwards.
- `sigsetjmp` tests all 64 bits of its `int` argument.
- A full callback pool, a `longjmp` across native code and a resume at an address the frame cannot continue from are all reported as "reached unsupported instruction".

### Tools and build

- `ps5lift` does not compile against LLVM 21 or newer, where `Module::setTargetTriple` takes an `llvm::Triple`; the build accepts any LLVM from 18 on.
- `--cpu native` appends the host's features after `--features`, so the host's win. `--triple`, `--cpu` and `--features` are not validated: an unknown CPU or feature warns and gives generic code, and a triple the host CPU cannot target aborts in a codegen thread after discovery.
- [generate_bridges.py](../tools/generate_bridges.py) exits 0 after libclang parse errors, whose recovered types make wrong prototypes. It ignores a `--libclang` path that does not exist, and sets the path only in the parent process, not in the workers that parse.
- Without the libclang Python bindings CMake leaves out the libc, exceptions, kernel and fiber tests with a status message, so ctest passes without running them.
- [build_runtime.py](../tools/build_runtime.py) rebuilds an object only when its source or a listed header is newer, not when the compiler, the flags or SoftFloat's `specialize.h` change, and keys its output directory by architecture alone.

## Gaps

- [Discovery](../lifter/src/Discovery.cpp) seeds functions from the entry point, `DT_INIT`, the exports, the `.symtab` function symbols, `.eh_frame`, relocation targets in executable segments and the addresses code takes with a RIP-relative `lea` (see the bugs above), then follows direct calls. It reads the init and fini arrays only through their relocations. A function only reached through a pointer that none of these finds stops at run time in `ps5lift_dispatch`.
- [Jump tables](../lifter/src/Discovery.cpp) whose guard is not recognised, such as one that compares a stack slot and loads the index from another, are sized by the data references around them. A reference into the table ends it early, which stops at run time in `ps5lift_dispatch` when a missing case runs; data that nothing refers to after the table, with words that happen to point into the function, adds entries, and one that lands inside an instruction stops the lift.
- [GuestImage](../lifter/src/GuestImage.cpp) applies `R_X86_64_64`, `GLOB_DAT`, `JUMP_SLOT` and `RELATIVE` at lift time, at the executable's link addresses and at the base `ps5lift` gives each module; `R_X86_64_DTPMOD64`, `DTPOFF64` and `TPOFF64` against the image's own symbols; any other relocation type, including copy relocations and TLS relocations against another image's symbols, stops the lift. An image's references to its own symbols are not interposed by an earlier image's, as `ld.so` would interpose them without `DT_SYMBOLIC`. PS5 inputs have to be relinked first; `ps5lift` does not read SELF or SCE dynamic tables itself.
- A `call` or `jmp` through an import slot is lifted as a direct call to the import, which is wrong if guest code rewrites that slot.
- [The runtime](../runtime/src/Runtime.cpp) maps the whole image read-write (through AnyPS5's guest arena when its libc is linked in), gives TLS only to the images loaded at start, not to modules loaded later, and runs modules' initializers but not the executable's nor any finalizer; the relinker's entry stub is the only entry contract tested.
- [The lifter](../lifter/src/Lifter.cpp) supports integer, BMI1/BMI2, atomic, `movs` and `stos` instructions, SSE/AVX2 integer and floating-point instructions, FMA3 and F16C. These are reported as unsupported and stop at run time: `dpps`, `dppd`, gathers, `vmaskmov`, `maskmovdqu` and `maskmovq`, the variable `vpermilps` and `vpermilpd` forms, `cmpxchg8b` and `cmpxchg16b`, `lods`, `scas` and `cmps`, `rcl` and `rcr`, `loop`, `loope` and `loopne`, `pushf`, `popf`, `lahf` and `sahf`, `xlat`, `enter`, `crc32` and SSE4.2's string comparisons, `psign`, `mpsadbw`, `phminposuw`, `rdrand`, `rdseed`, `rdtscp`, `rdpid`, `prefetchw`, `movnti`, `movntpd`, `movq2dq`, `movdq2q`, the conversions between MMX and SSE registers (`cvtpi2ps`, `cvtps2pi` and the rest), `vzeroall`, `xsave` and `xrstor`, the x87 instructions listed below, `syscall` and bit-string `bt` on memory with a register offset. So are SSE4a's `extrq` and `insertq`, which EVO Player uses. AES-NI and `pclmulqdq` lift on 128-bit registers only: VAES and VPCLMULQDQ on 256-bit registers are AVX-512-era extensions the reported Zen 2 lacks, and code that checks `cpuid` does not reach them. `shld` and `shrd` with 16-bit operands, whose counts above 16 give undefined results, and 16-bit `bswap`, which is undefined, stop as well.
- [`cpuid` and `xgetbv`](../runtime/src/Cpuid.cpp) answer as an AMD Zen 2: with the signature of AMD's 4700S desktop kit, which is built on the PS5's chip (family 17h, model 47h, stepping 0), and with the user-mode extensions LLVM enables for `znver2` plus the optional ones AnyPS5's host check lists for the console. None of it is measured on a console. The highest leaves reported are 0xd and 0x80000001, so code reads the cache, topology and brand-string leaves as absent; leaves 5 and 6 and `xgetbv` of a register other than XCR0 stop the program.
- An unaligned ordered load or store is a plain access with a fence. x86 makes an unaligned access within a cache line single-copy atomic; aarch64 makes a plain one atomic only within 16 bytes with FEAT_LSE2, and not at all without it. Locked instructions, `xchg`, `xadd` and `cmpxchg` still declare their natural alignment, so an unaligned one, a split lock on x86, faults. Vector loads and stores wider than 64 bits are not ordered.
- Lifted calls nest on the host stack, which the runtime sizes at 512 MiB for the guest thread. `longjmp` unwinds lifted frames ([Jump.cpp](../runtime/src/Jump.cpp)), but not native frames between them: a `longjmp` out of a guest callback that native code called stops the program. Guest C++ exceptions work when their personality routine is AnyPS5's (`__gxx_personality_v0` or `__gcc_personality_v0` imported by name or NID); a personality routine in guest code is not called. A fiber's guest entry point is stored as its callback thunk, so `sceFiberGetInfo` reports the thunk's address rather than the guest's. The target frame of a `longjmp` is the innermost one with a `setjmp` call whose entry stack pointer is at or above the saved one, which assumes the frame did not move its stack pointer above that value after `setjmp`.
- The status flags are not kept in the state: only DF crosses calls, returns and dispatch, or all of them with `--preserve-flags`. `pushf`, `popf`, `lahf` and `sahf` are not lifted.
- Under qemu 8.2.2 the lifted vector fixture built for `neoverse-v2` at -O0 (relaxed) and -O3 (TSO) crashes with SIGSEGV on a store to mapped, writable memory, and the same binary prints the expected output with `-one-insn-per-tb`; builds for `neoverse-n1` and every x86-64 build pass. The same `neoverse-v2` builds, SVE included, pass natively on the GB10 (`run_fixture.py --cpu neoverse-v2`), so this is a qemu translation bug. The test driver runs aarch64 code under qemu with `-one-insn-per-tb` to avoid it.
- [FMA](../lifter/src/Lifter.cpp) NaN priority (left multiplicand, right multiplicand, addend) was measured on an Intel Xeon; Zen 2 is unverified.
- `rcpps`, `rcpss`, `rsqrtps` and `rsqrtss` return the correctly rounded `1/x` and `1/sqrt(x)`, not Zen 2's approximations.
- `stmxcsr` reports the exception flags the host FPU raised; an operation that `--float exact` computes with integer code, such as `vcvtps2ph` with an immediate rounding mode, raises none.
- FTZ without DAZ, or DAZ without FTZ, is exact only on aarch64 CPUs with FEAT_AFP; elsewhere either bit flushes inputs and outputs. The fixtures only exercise both together.
- LLVM assumes the default floating-point environment, so an operation it constant-folds uses round-to-nearest whatever the guest MXCSR says.
- libkernel for a lifted guest: `getcontext`, `setcontext`, `swapcontext` and `sigreturn`, which switch guest stacks, report themselves as not implemented. A `sceKernelRaiseException` handler sees the registers of the target thread's last call, not of the instruction it interrupted, and its changes to the context are dropped. The dynamic linker binds a function that two libraries define to the first library linked, which is only right while both definitions behave the same; exports with C++ linkage, which AnyPS5 also publishes by NID, have no bridge.
- Data imports are told apart from function imports by the symbol's ELF type; an untyped undefined symbol is treated as a function. Copy relocations and TLS imports are not supported. AnyPS5's libc exports no type_info for fundamental types (`_ZTIi` and so on), so a guest that throws or catches one fails to link.
- [The bridge generator](../tools/generate_bridges.py) skips exports that return complex values, pass or return records by value, or take a function pointer as a callback's argument, and leaves `setjmp` and `longjmp`, which need the guest's own registers, to the runtime; it bridges only `extern "C"` exports. A variadic export calls its `v` sibling, which takes a `VaList*`, when it has one; one without forwards the remaining integer registers when its variable arguments start in a register, and is skipped otherwise. libc gets 1513 bridges and 40 exports have none. Records by value need the SysV classification of their fields. libkernel's variadic `open`, `fcntl` and `sem_open` read their optional argument with the host `va_arg` and have no `v` sibling yet.
- [Callbacks](../runtime/include/ps5lift/Bridge.hpp) take and return scalars only, and each signature has 256 thunks; the 257th distinct guest address for one signature stops the program. The guest state a foreign native thread gets on its first callback lives until that thread exits.
- [GuestCpu](../runtime/src/GuestCpu.cpp), the guest FPU state that a lifted AnyPS5 libc reads: x87 is only its control and status words, so `fegetenv` reports every x87 register empty; `fwait` with an unmasked pending x87 exception ends the program where the console raises SIGFPE; the MXCSR support mask is reported as `0xffff`, not measured on a PS5. Flags that lifted arithmetic raises reach `fetestexcept` through the host FPU, but LLVM may reorder or fold floating-point operations around a call because it assumes the default environment.
- AnyPS5 libc in lifted mode: all 68 sources compile for aarch64 and x86-64, and seven of upstream's libc test programs pass on both (`tools/run_libc_tests.py`). The rest of upstream's tests are not run yet. `GuestStdioVariadic`'s `_Vacopy` check reads the copy with the host `va_arg`, so lifted builds skip it. C++ exceptions thrown and caught by the libc itself use the host's unwinder in lifted builds; guest exceptions, which AnyPS5's own unwinder handles on x86 hosts, are not supported. A host caller's `long double` variadic argument is rounded to 80 bits before formatting.
- [x87](../runtime/src/X87.cpp): the transcendental instructions (`fsin`, `fcos`, `fsincos`, `fptan`, `fpatan`, `f2xm1`, `fyl2x`, `fyl2xp1`), `fxtract`, `fbld`, `fbstp`, `fsave`, `frstor`, `fxsave`, `fxrstor`, `fnop` and `ffreep` are reported as unsupported. `fprem` always finishes the reduction in one step, so C2 is never set, and the C bits of an `fprem` with a NaN result and the rest of the x87 behaviour were measured on an Intel Xeon, not on Zen 2. An unmasked x87 exception ends the program at the next `fwait`, not at the next x87 instruction, and `fnstenv` records zero instruction and operand pointers.
- [Guest long double](../3rdparty/anyps5/core/libs/prx/libc/include/GuestLongDouble.hpp): on aarch64 the libc's `long double` code computes in binary128 and rounds once to 80 bits, while the console rounds every x87 step to 64 bits, so a function of several operations can differ in its last bit, and round-to-nearest can round twice. When both operands of a host operation are NaNs, the host, not x87, picks which one comes back. The precision control in the x87 control word does not apply to host code. `long double` callbacks, `long double` complex results (`__mulxc3`, `__divxc3`) and the locale's `putLongDouble` member are not bridged. Host binary128 arithmetic on aarch64 is itself in software (libgcc), so a SoftFloat-backed guest type would cost about the same and remove these differences.

## Tests

- Every fixture is built for `znver2`, so the compiler encodes SSE with VEX, and the only legacy SSE forms tested are AES, `pclmulqdq` and MMX, which come from assembly. A build of `vector.c` and `float.c` for `x86-64-v2` would cover the rest.
- No test runs `--float fast`, `--preserve-flags`, an unoptimized lift or `--emit-ir`, and no fixture splits an image into more than one part, so calls between the parts of one image are tested only by EVO Player.
- Untested paths: locked bit operations, string instructions with live flags, division traps, overlapping instructions, jump tables sized by layout, fibers resumed on another thread, `sceKernelRaiseException`, `vcvtps2ph` with directed rounding, `fscale` by large scales, and the generator's forwarded variadics and 128-bit stack arguments.
- The TSO check in `threads.c` can only fail when the lifted code runs on aarch64 hardware. Only the libc fixture runner sets a timeout, so a hung lifted program blocks ctest.

## Cleanup

- [Lifter.cpp](../lifter/src/Lifter.cpp) is about 3150 lines, most of them one class. `EmitSemantics` falls back to trying five `Emit*` functions in turn, so which one owns a mnemonic is not stated anywhere, and instruction families are split across them: `shufps` and the immediate `vpermilps` are vector kinds while `shufpd` and `vpermilpd` are in `EmitFloat`, and the broadcasts are lifted from two places. `EmitVector` derives each kind's operand shape from lists of kinds. One table from mnemonic to handler would also be the place to check prefixes and branch types.
- Switches pick an operation for values they do not name instead of failing: `SignExtendAccumulator`, `BitScan`, `VectorBitwise`, `BitManipulation`, `Shift` and `ShiftDouble` in the lifter, `EmitVector`'s `default`, which reports a lifter bug as an unsupported guest instruction and hides `-Wswitch`, and the x87 runtime's `Arithmetic` and `CompareConditions`. `ps5lift_string_op` treats every operation other than 0 as `stos`; its enum exists only in the lifter, and the x87 constant indexes and comparison codes are bare numbers on both sides.
- Target selection is spread over `main.cpp` (the default CPU, by triple prefix), `Codegen.cpp` (the required features) and `Lifter.cpp` (the triple check), and the lifted module has no data layout until code generation.
- Duplicated: the in-lane masks of the integer and floating-point horizontal operations; the EFLAGS mapping of `fcomi` and `comiss`; the x87 runtime's 80-bit reads and writes and its rounding table, and its wait check, which `GuestCpuX87Wait` reimplements with its own exit; `Hex` in three files; the lift, link and run steps of the four fixture runners; the NID header in `run_libc_fixture.py`.
- Dead: `ImplicitGpr`, `LowElements`, `Broadcast`'s width fix-up, `AtomicRmw`'s `default`, `VZEROALL` in `FindUsedRegisters`, `Fpu::Operand`, `CalledImport`'s branch for a direct call to an import, the export of `ReturnsTwice` from its header, `emit`'s `library_name` parameter, the bodies in `libc_native.c`, the LLVM components the lifter links but does not use, and `ps5lift_thread_create` and `ps5lift_thread_join`, which only `host_bridge.cpp` uses.
- `GuestImage` is complete only after `PlaceTls` and `Relocate`; until then its imports and code pointers are empty, and nothing stops a caller from reading them. `Read` handles six concerns in one function.
- `pshufb` and `vpermd` are lifted as one variable-index extract per element, which aarch64 lowers through the stack; `tbl` does the same in one instruction.
