# Known gaps

- [Discovery](../lifter/src/Discovery.cpp) seeds functions from the entry point, the `.symtab` function symbols and `.eh_frame`, then follows direct calls. Stripped PS5 executables also need the targets of `R_X86_64_RELATIVE` relocations, the init and fini arrays and RIP-relative `lea` of code addresses; a function only reached through a pointer that none of these finds stops at run time in `ps5lift_dispatch`.
- [Jump tables](../lifter/src/Discovery.cpp) without a recognised bound are read while their entries point inside the function, which can stop one entry short when the table is followed by another code pointer into the same function, or include extra entries. Extra entries only cost code size.
- [GuestImage](../lifter/src/GuestImage.cpp) applies `R_X86_64_64`, `GLOB_DAT`, `JUMP_SLOT` and `RELATIVE` at lift time, so images must be at fixed addresses, as the AnyPS5 relinker writes them; any other relocation type, including the TLS ones, stops the lift. PS5 inputs have to be relinked first; `ps5lift` does not read SELF or SCE dynamic tables itself.
- A `call` or `jmp` through an import slot is lifted as a direct call to the import, which is wrong if guest code rewrites that slot.
- [The runtime](../runtime/src/Runtime.cpp) maps the whole image read-write, sets up static TLS for one thread only and does not run init arrays; the relinker's entry stub is the only entry contract tested.
- [The lifter](../lifter/src/Lifter.cpp) supports integer, BMI1/BMI2, atomic and string instructions, SSE/AVX2 integer and floating-point instructions, FMA3 and F16C. `dpps`, `dppd`, gathers, `vmaskmov`, the variable `vpermilps` and `vpermilpd` forms, x87, `pushf`/`popf`, `cpuid`, `rdtsc`, `syscall` and bit-string `bt` on memory with a register offset are reported as unsupported and stop at run time.
- Ordered loads and stores declare their natural alignment. x86 allows unaligned accesses; on aarch64 an unaligned `LDAPR` or `STLR` that crosses a 16-byte boundary faults even with FEAT_LSE2. Vector loads and stores wider than 64 bits are not ordered.
- Lifted calls nest on the host stack, which the runtime sizes at 512 MiB for the guest thread. Guest code that leaves a function without `ret` (longjmp, exception unwinding, fibers) is not supported yet.
- The flags register is reconstructed on every flush; `pushf`, `lahf` and `sahf` do not read it yet.
- Under qemu 8.2.2 the lifted vector fixture built at -O0 (relaxed) and -O3 (TSO) for aarch64 crashes with SIGSEGV on a store to mapped, writable memory, and the same binary prints the expected output with `-one-insn-per-tb`; builds for `neoverse-n1` and every x86-64 build pass. The test driver therefore runs aarch64 code under qemu with `-one-insn-per-tb`. Running the fixtures natively on an aarch64 machine decides whether this is a qemu translation bug or a lifter bug.
- [FMA](../lifter/src/Lifter.cpp) NaN priority (left multiplicand, right multiplicand, addend) was measured on an Intel Xeon; Zen 2 is unverified.
- `rcpps`, `rcpss`, `rsqrtps` and `rsqrtss` return the correctly rounded `1/x` and `1/sqrt(x)`, not Zen 2's approximations.
- MXCSR exception flags are not tracked; `stmxcsr` returns the flags of the last `ldmxcsr`.
- FTZ without DAZ, or DAZ without FTZ, is exact only on aarch64 CPUs with FEAT_AFP; elsewhere either bit flushes inputs and outputs. The fixtures only exercise both together.
- LLVM assumes the default floating-point environment, so an operation it constant-folds uses round-to-nearest whatever the guest MXCSR says.
- [The bridge generator](../tools/generate_bridges.py) skips exports that take or return `long double` or complex values, are variadic, pass records by value or return function pointers, and it bridges only `extern "C"` exports. Records by value need the SysV classification of their fields, and variadic functions need AnyPS5's formatting to read a SysV `va_list`.
- [Callbacks](../runtime/include/ps5lift/Bridge.hpp) take and return scalars only, and each signature has 256 thunks; the 257th distinct guest address for one signature stops the program. The guest state a foreign native thread gets on its first callback lives until that thread exits.
- [GuestCpu](../runtime/src/GuestCpu.cpp), the guest FPU state that a lifted AnyPS5 libc reads: x87 is only its control and status words, so `fegetenv` reports every x87 register empty; `fwait` with an unmasked pending x87 exception ends the program where the console raises SIGFPE; the MXCSR support mask is reported as `0xffff`, not measured on a PS5. Flags that lifted arithmetic raises reach `fetestexcept` through the host FPU, but LLVM may reorder or fold floating-point operations around a call because it assumes the default environment.
- AnyPS5 libc in lifted mode: 59 of its 68 sources compile for aarch64 (`tools/check_libc_port.py`). The other nine assume the host `long double` is x87's or that the host `va_list` is the SysV one. The changes live on the local `aarch64-host` branch of the AnyPS5 submodule until it has a fork to push to.
- [x87](../runtime/src/X87.cpp): the transcendental instructions (`fsin`, `fcos`, `fsincos`, `fptan`, `fpatan`, `f2xm1`, `fyl2x`, `fyl2xp1`), `fxtract`, `fbld`, `fbstp`, `fsave`, `frstor` and `fxsave` are reported as unsupported. `fprem` always finishes the reduction in one step, so C2 is never set, and the C bits of an `fprem` with a NaN result and the rest of the x87 behaviour were measured on an Intel Xeon, not on Zen 2. An unmasked x87 exception ends the program at the next `fwait`, not at the next x87 instruction, and `fnstenv` records zero instruction and operand pointers.
